## 2026-05-04

- `src/models.py` (`build_convnext_tiny`): Added ConvNeXt-Tiny wrapper as the "modern CNN" stretch model for the 48h-sprint comparison vs DAN. Uses `torchvision.models.convnext_tiny` with `IMAGENET1K_V1` weights, swaps `classifier[2]` (Linear 768→1000) for `Linear(768, num_classes)`. Registered in `MODEL_REGISTRY` as `"convnext_tiny"`. Smoke-tested locally: 27.8M params, forward `[2,3,224,224]` → `Tensor[2,7]`. Hooks to `report.md:488` (EmoNeXt's backbone family).
- `configs/convnext_fer2013.yaml`: ConvNeXt-Tiny training config with lr=1e-4 (lower than DAN's 3e-4 because the ImageNet head is more delicate), weight_decay=5e-2 (ConvNeXt paper default), 30 epochs, AMP, class-weighted sampler ON. Same image_size=224 and seed=42 as DAN config so the two runs are directly comparable.
- `tests/test_train_eval.py` (`test_convnext_builds_and_forwards`): Pytest smoke asserting ConvNeXt builds with ~28M params, returns a `Tensor` (not a tuple, unlike DAN), and goes through the registry. Suite stays at 11/11 green.
- `src/data.py` (`build_transforms`): Added `augment: bool = True` parameter. When `train=True` and `augment=False`, the train transform falls through to the eval pipeline (deterministic Resize → CenterCrop → Normalize). Used by the no-augmentation ablation so the only thing changing across runs is the augmentation policy. Verified locally: train+augment = 8 transforms, train+noaug = eval = 4 transforms.
- `src/models.py` (`build_dan`): Added `use_imagenet_init: bool = True` parameter. When False (and no `pretrained_ckpt`), the ResNet-18 backbone stays at random init from DAN's own constructor — quantifies transfer-learning contribution for the no-imagenet ablation. Verified that random vs ImageNet first-conv weights actually differ.
- `src/models.py` (`build_model`): Now accepts `**kwargs` and forwards them to the registered constructor. Lets ablation configs add knobs like `use_imagenet_init` directly under the `model:` block without changes to the dispatcher.
- `src/train.py` (`make_dataloaders`, `main`): Reads `data.augment` (default `true`) from config and passes it through; collects all non-core keys (anything other than `name`, `num_classes`, `pretrained_ckpt`) under `model:` and forwards them as `**model_kwargs` to `build_model`. Means new ablation flags can be added by just touching the config + the relevant builder.
- `configs/ablations/dan_no_sampler.yaml`, `dan_no_augment.yaml`, `dan_no_imagenet.yaml`: Three ablation configs, each turning off exactly one component (class-weighted sampling / data augmentation / ImageNet init), 10 epochs each (~17 min on T4) for the report's 3-row ablation table.
- `src/eval.py` (`build_tta_transform`, `tta_predict`): Added 10-crop test-time augmentation. The transform uses `torchvision.transforms.TenCrop` to produce 5 spatial crops × {orig, hflip} = 10 views per sample, normalized with ImageNet stats. `tta_predict` reshapes `[B, K, 3, H, W] → [B*K, 3, H, W]` for batched forward, then averages softmax over K and argmax. CLI `--tta` flag wired through `main()`; eval batch size auto-divides by 10 to keep peak GPU memory similar to single-crop. Output goes to `runs/<exp>/eval_tta/` (instead of `eval/`) so single-crop and TTA results coexist. Smoke-test verified: TTA dataset returns `(10, 3, 224, 224)` per sample, DataLoader batches to `(2, 10, 3, 224, 224)`, `tta_predict` produces valid predictions.
- `src/eval.py` (`main`): Now also forwards model_kwargs (e.g. `use_imagenet_init=False` for ablation eval) to mirror the train.py change. Required so ablation checkpoints can be evaluated with the same model config they were trained with.
- `notebooks/05_train_convnext.ipynb`: Training driver for ConvNeXt-Tiny. Slimmer than `02_train_dan.ipynb` because no third-party repo is needed (torchvision provides ConvNeXt + ImageNet weights). Includes a head-to-head metrics-comparison cell that reads both `runs/dan_fer2013/eval/metrics.json` and `runs/convnext_fer2013/eval/metrics.json` and prints a 2-row pandas table.

## 2026-05-01

- `notebooks/01_colab_setup.ipynb`: Loosened the FER-2013 ingest cell to accept either `fer2013.zip` or a bare `fer2013.csv` on Drive — saves the user a zip step. RAF-DB stays opt-in via `rafdb.zip` (EULA-gated, not blocking 24h plan).
- `notebooks/02_train_dan.ipynb`: Pivoted to 24h-mode — header now documents the FER-2013 default + RAF-DB full-mode, training command points at `configs/dan_fer2013.yaml`, eval points at `runs/dan_fer2013/best.pth`. The DAN-checkpoint-copy cell is replaced with a no-op print since 24h-mode trains from ImageNet init (no MS-Celeb-1M file required).
- `configs/dan_fer2013.yaml`: Halved epochs (30 → 15) and warmup (2 → 1). With ~100s/epoch on T4 + ImageNet-init backbone, this drops training from ~50 min to ~25 min, leaving headroom for eval + report writing within the 24h budget. Bumping back to 30 is a one-line change if WAR plateaus.
- `src/models.py` (`build_dan`): Fixed two bugs found by cloning `yaoing/DAN` locally and inspecting the code. (1) Import path was `networks.DAN` (case-sensitive); the file is `networks/dan.py` lowercase. (2) Calling `DAN(pretrained=True)` hard-codes a load of `./models/resnet18_msceleb.pth` (MS-Celeb-1M backbone), which we don't have — guaranteed crash. Fix: build DAN with `pretrained=False`, then post-hoc copy torchvision's ImageNet ResNet-18 weights into `model.features` (which is `Sequential(*list(resnet.children())[:-2])`). End-to-end smoke test passes: build_dan() → 19.7M params, forward `[2,3,224,224]` → `(logits[2,7], features[2,512,7,7], heads[2,4,512])`, train_one_epoch + evaluate run without errors. ImageNet init is ~1-2 pt below MS-Celeb-1M for FER fine-tuning, acceptable cost vs. hunting for the MS-Celeb-1M file.

## 2026-04-30

- `.gitignore`: Initial ignore rules — exclude data/, checkpoints/, runs/, third_party/, Python bytecode, notebook checkpoints, and `.claude/` (local Claude tooling state). Keeps the repo focused on source code, not artifacts or per-user tooling.
- `CLAUDE.md`: Authored the project rules file — locks in datasets/models, enforces CHANGES.md + per-change git commits, marks research/ read-only. Required so future sessions stay consistent with the approved plan.
- `CHANGES.md`: Created the change log with seed entries for the bootstrap files. Establishes the documentation discipline from the first commit.
- `requirements.txt`: Pinned floor versions for torch/torchvision/numpy/pandas/pillow/scikit-learn/matplotlib/seaborn/pyyaml/tqdm/gradio/opencv-headless/grad-cam/pytest. Floors (not exact pins) so Colab's preinstalled torch is reused without conflict.
- `scripts/prepare_fer2013.py`: One-shot script to materialize FER-2013 from the Kaggle CSV into per-split per-class PNG folders + manifest.csv. Needed because `src/data.py` is manifest-driven and the Kaggle release ships pixels packed into a single CSV column.
- `scripts/prepare_rafdb.py`: One-shot script to parse `list_patition_label.txt` and remap RAF-DB's native 1..7 labels to the project-canonical 7-class order (matching FER-2013) so cross-dataset evaluation lines up class indices without runtime bookkeeping.
- `src/__init__.py`: Empty package marker so `from src.data import ...` resolves cleanly.
- `src/data.py`: Implemented `FER2013Dataset`, `RAFDBDataset` (both manifest-driven, RGB-tiled), `build_transforms` (train uses RandAugment+ColorJitter+RandomErasing; eval uses Resize+CenterCrop), and `class_weighted_sampler` (inverse-frequency `WeightedRandomSampler` to counter the report-flagged Disgust/Fear imbalance on both datasets).
- `tests/__init__.py`, `tests/test_data.py`: Pytest smoke suite using a synthetic 14-image manifest in tmp_path. Covers shape, label range, DataLoader batching, sampler rebalancing, and the missing-manifest error path. Verified locally in `.venv/` (CPU torch 2.11.0 + torchvision 0.26.0): all 5 tests pass.
- `prepare_fer2013.py`: Verified on a synthetic 14-row CSV — produces correct splits (train/val/test), all 7 labels, and class-named subdirectories on disk.
- `notebooks/01_colab_setup.ipynb`: Colab entrypoint — mounts Drive, clones repo, installs deps, unpacks `fer2013.zip`/`rafdb.zip` from `MyDrive/fer-data/`, runs prep scripts, runs pytest, and renders a 4×4 sample grid. Designed so a fresh Colab session reaches "trainable state" by running cells top-to-bottom.
- `src/models.py`: Added `build_dan` and `build_poster_pp` wrappers with a shared `MODEL_REGISTRY`. Both lazy-import from `third_party/<repo>/` so this module remains importable without the third-party repos cloned (failure surfaces only when actually building a model). Wrappers tolerate `model_state_dict`, `state_dict`, and bare-state-dict checkpoint formats and strip `module.` DDP prefixes, since DAN and POSTER++ release checkpoints in slightly different formats.
- `configs/dan_rafdb.yaml`, `configs/dan_fer2013.yaml`: Hyperparameter configs. RAF-DB config disables the class-weighted sampler (RAF-DB reports use uniform sampling and report UAR alongside WAR per report.md:2210); FER-2013 config enables it (severe Disgust imbalance per report.md:1928). Both use AdamW + cosine + AMP; FER-2013 trains longer (30 epochs) since we don't have a pretrained checkpoint to bootstrap from.
- `src/train.py`: Generic, model-agnostic training loop. Defensively unpacks model output (DAN returns `(logits, features, heads)`; POSTER++ returns logits); records WAR/UAR per epoch in `runs/<exp>/log.jsonl`; saves `best.pth` on UAR (not WAR) so an imbalanced-class collapse can't win. AMP enabled when CUDA + config flag both present.
- `src/eval.py`: WAR/UAR/per-class precision/recall/F1, confusion matrix as both PNG (normalized + counts) and CSV. Outputs to `runs/<exp>/eval/`.
- `src/predict.py`: `Predictor` class for single-image inference. Lazy model load; tolerant to multiple checkpoint formats; used by the Gradio app and the CLI demo.
- `tests/test_train_eval.py`: Smoke tests using a `TinyClassifier` (3*32*32 → 7 logits) on a 56-image synthetic dataset. Exercises `train_one_epoch`, `evaluate`, `confusion_matrix`, `per_class_metrics`, `collect_predictions`. All 10 tests in the repo now pass locally.
- `configs/poster_rafdb.yaml`: Stretch-model config with batch=32 (43.7M params on T4), epochs=5, lr=1e-5 (small to avoid catastrophic forgetting from a near-SOTA released checkpoint), AMP enabled. Documents the report's "never train from random init" requirement (report.md:933-934) inline.
- `app/__init__.py`, `app/gradio_app.py`: Gradio demo with model selector (DAN vs POSTER++), image-upload tab, webcam tab, top-3 probability output. Predictors are cached lazily — first call per model triggers the load. UI build verified locally with gradio installed in `.venv/`.
- `notebooks/02_train_dan.ipynb`: Week-2 driver. Clones DAN repo, copies released checkpoint from Drive, runs train + eval, displays the confusion matrix.
- `notebooks/03_train_poster.ipynb`: Week-3 driver with explicit reproduce-first protocol — eval the released POSTER++ checkpoint and STOP if WAR < 91% before any fine-tuning. Copies IR-50 + MobileFaceNet pretrained backbones into `third_party/POSTER_V2/models/pretrain/`.
- `notebooks/04_analysis.ipynb`: Cross-dataset eval (RAF-DB ↔ FER-2013), top-confident-wrong failure gallery, and a stub for per-attribute fairness analysis on RAF-DB. The fairness cell is intentionally a stub because the exact RAF-DB attribute file layout depends on which version was downloaded — to be filled in after the EULA-gated archive is unpacked.
